## Implemented boundary

Reviewed E47_PAPER_ENGINE_REVIEW_AND_READINESS.md and actual dataset loader,

The earlier E1/E2/E3 and paper contracts intentionally admitted only synthetic
sources. Passing real inputs through those APIs with a SYNTHETIC label would be
incorrect. E5 instead adds a file-bound, in-process source capability:

1. `e5_source.load_source` verifies actual input snapshots, both historical dataset
   qualifications, E4.7 checks, independent adapter assertions and frozen policies.
2. It validates raw-to-normalized mapping, extended outcome-prefix equality, native
   Bid/Ask OHLC consistency, explicit candle availability/finality/corrections,
   dated financial documents and actual quote/trade phases. Unknown means blocked.
3. Only after all checks and final unchanged-file checks does the loader register
   an owned source. Matching provenance strings, reviewer names or checksums alone
   cannot create this capability. No function writes an APPROVED review.
4. `paper_source_scope` binds that source to a scoped, single-owner replay. E1
   contexts must match hashes produced by that source; quote dataclasses must
   match actual captured rows and permissions; specs/costs must match the frozen
   documents. Another source or unscoped caller cannot mutate its account.
5. Existing algorithms perform the analysis, sizing, fills and protection. The
   unchanged SR ledger is reused through its existing historical evaluator.
   E4.7's canonical journal type check and pre-mutation prefix authentication remain.

This is not a hostile-Python sandbox, digital provider authentication or independent
human approval. Private producer state remains private by convention, as in the
existing engine. A person must independently examine the evidence; code validates
file-bound declarations and mechanics, not the truth of invented documents.

Legacy public APIs without an admitted source retain their synthetic-only gates
and output contracts. There is no HTTP route, live MT5 acquisition, order dependency,
credential lookup, AI activation, daemon or live paper bridge. Source admission
never changes execution_allowed or any broker/calendar verification flag.

Native data retain HISTORICAL_RESEARCH provenance; historical quote/fill report
names and receipt-price assumptions are distinct. The legacy numerical carrier
class names and frozen policy identifiers containing SYNTHETIC are retained for
compatibility: they identify the original hypothetical model, not a relabeling of
native data. `account_is_synthetic` still means the capital account is virtual.
Original detector/setup identities are unchanged. Source/configuration bindings
are separate; repeated qualification of one setup is not a new opportunity.

## Required private file graph

The CLI accepts an adapter plan and a separate independent adapter review. Reuse
PR54's bundle schema; do not rewrite it into a weaker gate.

Plan fields are exactly `version:1`, `protocol_sha256`, `inputs`. Inputs have these
seven roles, each a safe relative local `{file,sha256}` reference:

| Role | Required content |
|---|---|
|manifest / review|Existing v2 evaluation manifest and actual independent historical qualification review|
|paper_bundle|Exact E4.7 evidence bundle, including raw M1/M5, quote events, spec/cost/policy artifacts and evidence documents|
|outcome_manifest / outcome_review|Separately qualified extended M1/M5 inputs with identical warm-up, feed, basis and calendar; evaluation end extends to outcome end|
|import_spec|Existing qualification-assistant v1 explicit raw CSV column mapping, authorized local use, native frame identity/finality/correction declarations|
|bar_availability|Per-row provider evidence described below; never created by inferring receipt time from candle opening|

Evaluation and extended normalized prefixes must match exactly. Raw native M1/M5
are parsed using the existing importer and must match the extended normalized
rows. M5 must be NATIVE_SAME_FEED; aggregation is a diagnostic, never substituted
for executable or native data. Each raw frame must declare a supported finality
contract and no known corrections; unknown/corrected inputs remain blocked until
a separately reviewed as-of revision adapter exists.

The old manifest v2 ends its candle range at evaluation end. The separate extended
manifest solves this without pretending later outcome candles were available
before evaluation. No new entries occur in that tail. Both qualifications must
pass, including native M1/M5 coverage, closed-candle/session checks and independent
evidence reviews. Existing synthetic calendars remain ineligible for real admission.

Bar availability CSV has exact columns:

```text
timeframe,opened_at_utc,closed_at_utc,available_at_utc,revision,finality
```

Every normalized M1/M5 bar appears once in frame order. UTC scheduled close must
match its nominal M1/M5 interval; availability must be at/after that close. FINAL,
revision0 and full verified session geometry are required. Partial session candles,
future availability contradictions, missing rows, duplicates and unknown corrections
block. Provider finality/availability evidence is independently reviewed; age or
MT5 time_msc alone cannot establish when the strategy knew a finalized candle.

Quote event CSV reuses PR54's strict fields:

```text
sequence,occurred_at_utc,available_at_utc,bid,ask,revision,finality
```

Prices come exclusively from these native events. No OHLC-derived executable price,
receipt timestamp, missing candle, guaranteed stop fill or slippage is manufactured.
Occurrence order cannot decrease, receipt order must strictly increase, and sequence
must be contiguous. Duplicate/corrected rows are not silently deduplicated or repaired.
Unchanged prices with genuinely new occurrence/receipt records remain distinct.
Late receipt does not refresh the quote's occurrence age for the paper engine.

Warm-up counts use both close and availability at evaluation start. Minimum counts
are derived from the unchanged indicator windows (currently15 per frame), not a
new trading threshold. Confirmed pivots/zones still have to exist for the original
rule; adequate history does not invent structural evidence or force an entry.
Earlier native M5 warm-up may precede M1 coverage under the existing declarations.

## Chronological replay and reporting

`e5_replay.replay_source` merges M1 nominal closes with actual native quote receipt
events. A close is processed before a coincident quote receipt. A new entry requires
the original strictly-after-decision/latency rule; the coincident quote is not
silently treated as a future executable observation. Context contains only candles
whose verified close and availability are at/before its cutoff. Late M5 publication
cannot leak the finished bar into an earlier M1 context. Existing freshness rules
still determine whether older available data are usable.

Every warm-up close updates the original entry lifecycle; warm-up is state-only.
First qualifications strictly after evaluation start and at/before evaluation end
are counted once. Qualified warm-up carry-ins cannot become new evaluation entries.
When setups compete for the single position, deterministic setup-ID order and the
existing capital rules determine admission; other opportunities record rejection.
A setup's original qualification, current analytical state and native fill receipt
are kept separate. No new setup is created by repeating the same qualified report.

Each snapshot and append-only opportunity transition records its UTC time, evidence
hashes, outcome/reasons and source/configuration bindings. Latest opportunity status
is separate from its event history. Pending quotes/open positions/unresolved exits
are visible, not profitable closes or zero-loss observations. Exhausted/negative
balances are retained and cannot be replenished.

Reports provide opportunity/accepted/rejected/blocked/unresolved counts, entry/exit
records, source/phase coverage, native journal, net hypothetical P&L, resolved-trade
win rate/profit factor/expectancy, drawdown, equity curve, explicit costs and capital
survival. Empty denominators remain null. Explicit commission/fees/financing reconcile
to ledger transaction costs; modeled slippage and native spread are embedded in fill
prices and are not deducted a second time. Entry/exit efficiency remains unmeasured
without a reviewed reference definition. End-of-input review never forces a close;
equity at a later unobserved cutoff is unknown rather than a fabricated current mark.

`run_historical` loads and runs two independent full episodes and a common-cutoff
prefix episode. It compares complete full reports/admission bindings and hashes,
plus the overlapping journal, snapshot and opportunity-event prefixes. The default
common cutoff is evaluation end before the outcome tail. Integrity preflight may
inspect the full archive; analytical callbacks consume only cutoff-eligible records.
Appending a new file changes its file/dataset identity and requires fresh review;
that identity change is separate from causal evidence or outcome revision.

If any source, review, model or replay comparison fails, historical metrics remain
null/UNMEASURED and comparisons NOT_RUN. A successful future qualified run reports
hypothetical accounting under the reviewed model, not broker execution, profitability
certification or live readiness. Historical validation remains PENDING and all
execution/Exness gates remain blocked.
